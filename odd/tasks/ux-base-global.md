# UX base: no zoom, clear errors, session, error screens, PWA

Objective: the global fixes every page benefits from, before the ONs redesign and the page-by-page pass (user chose this order, L2).
Branch: `feat/ux-base` (from `origin/master` 3bf06ae). Delivery: ask-on-risk; work-unit commits, PR slicing decided at push time. Test runner: vitest (`npm test`, `npm run type-check`, `npm run lint`).

## Specs

Specs come from the 2026-10-23 read-only audit (engram `ux/audit-2026-10-23`); the user's words are in L1-L2.

- S1 (zoom): "Hay muchos formularios o muchas veces con hacer doble clic o zoom así" → on a touch device, focusing any field never zooms the page and a double tap never zooms. Pinch zoom keeps working (accessibility). Evidence: body font is 14px (`globals.css:68`) and every input inherits it; iOS zooms on focus below 16px. No `touch-action` anywhere.
- S2 (errors): "Muy importante también que el usuario entienda bien cuando hay un error o qué pasó" → every error message an API route sends to the browser is in Spanish, says what happened and, when there is one, what to do; never internal text. A validation error names the problem of the first invalid field. Login shows Spanish messages for Supabase auth errors. Evidence: ~112 of 135 literal API errors are English (`'Unauthorized'` in `api-auth.ts:31`, `'Internal error'` ×27, `'Validation failed'`); the UI shows `error` verbatim; `validation.ts` reads `error.errors`, which zod v4 does not have, so field details are always lost.
- S3 (session): when the session has expired, the user is told so in Spanish, and after signing in again lands on the page they were on (same-origin path only).
- S4 (error screens): a render failure, a chunk that fails to load after an update, or an unknown URL shows a Spanish screen in the app's theme with a way out (retry, reload, go to Resumen), never Next's English default. Evidence: no `error.tsx`, `global-error.tsx` or `not-found.tsx` in `src/app`; unknown paths are forced to dark (`theme.ts:21`).
- S5 (PWA): "Quiero que apuntemos a hacer una PWA de primera mano" → manifest in Spanish with the current palette, opens at the Resumen, no orientation lock, a separate maskable icon, an opaque iOS icon, shortcuts to the main sections; a Spanish offline page when a page cannot load without connection; a notice when the connection drops and when it comes back; a notice when a new version was installed.
- S6 (quality bar): "tiene que ser facil de entender y facil de usar" → plain Spanish copy with the app's voseo, no jargon; every touched screen works 320–1920 px with no horizontal scroll, light and dark, 44 px touch targets on phones.

Out of scope here (later projects, agreed order L2): ONs redesign; per-page fixes (silent failures, success feedback, modals closing on backdrop tap, UTC dates in Gastos, alerts only via Telegram, native `confirm()`). Also deferred: forgot-password flow, `viewport-fit=cover` + safe areas (needs a real iPhone), install screenshots.

- L4: production findings. (a) The manifest `start_url`/`scope` pointed at `portfolio.fratellipastas.com` while the app is served at `warren.fratellipastas.com`: a different origin, so browsers ignored them; now relative. (b) The service worker was NEVER registered in production: next-pwa 5.6 injects its registration only into `main.js` (Pages Router), which App Router pages never load. `AppStatus` registers `/sw.js`; `register: false`. (c) Once registered, the install failed: `/_next/app-build-manifest.json` is in the precache and 404s; excluded in `buildExcludes`. (d) Turning the worker on with next-pwa's default rules would cache pages and RSC payloads (`others`, 24 h), Supabase Auth and Binance responses (`cross-origin`), and `/` (`start-url`) on the device past logout. Now only static fonts, images, JS and CSS are cached; navigations are `NetworkOnly` with the `/offline` fallback; `cacheStartUrl` and `dynamicStartUrl` off. Probed on a production build (next start :3107): worker active and controlling, offline navigation to `/ons/mi-cartera` shows "Sin conexión", device caches hold only icons, manifest, `/offline` and `/_next/static`, a changed `sw.js` raises "Hay una versión nueva de Warren".
